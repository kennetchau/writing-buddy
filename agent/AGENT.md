# Decided architecture (from v2.0 docs — do not re-litigate)
- **One Node.js + TypeScript app**, server-rendered (Express + hbs + small vanilla TS + SSE). NO React, NO Vite, NO FastAPI.
- **PostgreSQL** for all data (schema in backend doc §2): lore is markdown **text columns**; no filesystem lore, no symlinks, no git, no version history. `story.universe_id` nullable = primary universe (original world). Borrowed concepts = outline markdown links `[Display](target)`, resolved at Verify/generate time — not stored.
- **Images**: one flat dir, path in DB. **Auth**: argon2id + cookie, no lockout; admin flag = user management only.
- **AI = on-trigger only** (buttons, never background), one action per user, streamed SSE: generate chapter (outline + primary-universe lore + matched-link entries + all summaries + last 2 chapters), summarize, lore suggest, image→description. Lore adds apply directly, **deletes require confirm** (only approval step).
  - **Generate has two modes** (post-build polish, see todo.md): with no chapter open the button is "Generate next chapter" (append a new draft); with an existing *draft* open in the pane it becomes "Generate this chapter" — regenerates that chapter **in place** (`POST /api/ai/generate` takes optional `chapter_seq`; final chapters refuse; stale summary cleared) and the prompt adds a `CURRENT_CHAPTER` section (existing title + body) with the instruction "Rewrite chapter N now". Final chapters can never be overwritten.
  - **AI activity is named, not just flagged**: `GET /api/ai/current` includes the run's target title (story name / image entry), so the navbar badge says *which* story is being written on every page; the story page locks itself (indicator + disabled inputs/buttons) when its own run is active.
- **Client JS** (CR round 3, 2026-10-11 — FR-12/13): pages stay vanilla JS, with **one bundled client module** — `src/public/js/story.ts` (excluded from tsc; the **esbuild** devDependency bundles it into a static iife `/js/story.js` via the `build:js` npm script). It gives the story page **CodeMirror 6** markdown editors for outline + chapter body (single pane, live-rendered — `marked` was discussed and dropped because CM6 renders inline). The **outline** editor has a `/keyword` autocomplete: typing `/star` calls `GET /api/lore/search` (pure Postgres FTS prefix + `ILIKE` substring over the user's accessible entries, title weighted; empty `q` = browse) and selecting a suggestion inserts a **standard `[Title](Title)` link** — no new syntax, so Verify/generate are untouched and no schema change. All page JS reads/writes editors only via `window.storyEditors` (a textarea-backed stub that the inline script creates, swapped in by the bundle) — the page fully works if the bundle fails. Don't add a second bundler or another client framework; keep editor code in that one entry. Client behavior is regression-tested headlessly in `tests/client-story-editor.spec.ts` (vitest + jsdom, 5 cases, driving the real CM6 source — see lesson 9).
- **Verify** = pure string match, no AI. System prompts: one per action, editable, no versioning.
- **Deploy: systemd quadlet (podman)** — `novel-app` + `novel-db` (postgres) containers, shared network, existing llama.cpp untouched (T5.3).

# Hard-won lessons from the old build (reference/story_creator — read-only)
1. **The local model is slow** (CPU-quantized Gemma 31B): every AI action MUST stream (SSE) with a visible "AI working" indicator everywhere; LLM read timeout 900s.
2. Old build failed via scope creep (7 AI roles, symlink/git lore, proposals, 14 checkpoints). **Resist adding anything not in the BRD.**
3. Host quirks (Fedora, rootless podman + pasta, SELinux Enforcing): bind mounts need `:z`; chown data dirs from inside the image; quadlet generator rejects `ExtraHosts` and does no variable expansion. See `reference/story_creator/deploy/DEPLOYMENT.md` + CP-1 in `reference/story_creator/plan/checkpoints.md`. **Quadlet `PublishPort=` MUST be two-number `host:container` — a bare `PublishPort=9187` lands on a random host port (podman docs: "not listing a host port means Podman automatically selects one"). And the install script must `restart`, not `start`, the container units — `start` is a silent no-op on re-runs.** (Both hit live 2026-10-06; see `agent/issue-autologout.md`.)
4. Local models emit messy JSON — parse all structured LLM output defensively (`reference/story_creator/app/llm/verdict.py`).
5. Fake-LLM test pattern (`reference/story_creator/tests/fakes`) let the old build test without a model — port the idea (T4.1).
6. **Express `res.cookie` `maxAge` is in MILLISECONDS, but the wire `Max-Age` is SECONDS.** Passing the 12h value in seconds (`43200`) silently produces `Max-Age=43` → the browser expires the session cookie after ~43s → the "force logout" bug (found 2026-10-07; the earlier cert + browser theories were red herrings). Guard with the shared `SESSION_TTL_MS` constant in `src/auth/session.ts` and the regression test in `tests/phase1.spec.ts` that asserts the emitted `Max-Age=43200`. Rule of thumb: when a login "expires by itself after a fixed short time", check the actual `Set-Cookie` bytes on the server (`curl -sk -D - -o /dev/null -X POST .../api/login | grep -i set-cookie`) before blaming the browser.
7. **Fake-LLM canned responses are sticky (`last` repeats once the queue drains), so a run that fails BEFORE its chat call leaks its queued response to the next test.** Symptom: a test's AI run finishes in ~2 ms with *another* test's text (e.g. "Overwrite?") and anything that polls for the run to be active never sees it. Fix: `fakeLlm.reset()` at the top of every AI test (done in `tests/phase4.spec.ts`); if a run under test must stay observable, give it enough `delayPerChunkMs` chunks to outlast the polling gap.
8. **`cp -r views dist/views` silently nests (`dist/views/views/`) once `dist/views` exists**, so a re-run build leaves the top-level templates STALE — the app boots fine but serves old templates and it looks like "my template edit did nothing". Found 2026-10-09 (round-2 smoke test served Oct-7 templates; the Docker build stage is fresh each run, so prod never hit it). The build now does `rm -rf dist/views &&` first. Rule of thumb: if a template edit "doesn't take", check `ls -la dist/views` (mtime + a nested `views/` dir) before suspecting the template. Also from that round: a table-level `UNIQUE (col, lower(col))` constraint is invalid SQL in Postgres — use a `CREATE UNIQUE INDEX`.
9. **CM6 autocomplete: a *Promise in `CompletionResult.options`* silently yields an empty dialog** — the async part belongs in the *source* (return a Promise from the source function), and the result's `options` must be a plain array at that point. Symptom: source runs (you see the network call) but no dropdown. Found 2026-10-11 via a headless repro.
10. **CM6 re-filters returned options against the completion range by default (`sortOptions` fuzzy match), so options whose labels don't contain the typed trigger (e.g. `/` for lore search) are all dropped → dialog never opens.** When the server already did the search, set `filter: false` on the source so the returned list is shown verbatim. Same repro/fix as lesson 9; the guard is `tests/client-story-editor.spec.ts` (vitest + jsdom drives the real CM6 source — the pattern to copy for future client-side behavior: stub `fetch`, type into the real editor, assert on the doc).
11. **hbs `{{…}}` HTML-escapes its value EVEN INSIDE `<script>` blocks — raw JSON/JS template locals must use triple braces** `{{{…}}}` (the `{{{borrowedJson}}}` pattern). `JSON.stringify` always emits quotes, so a double-braced local like `{{storyTitleJson}}` renders `const X = &quot;…&quot;` → a SyntaxError that silently kills the ENTIRE page script. Symptom: "clicking ANY button on the page does nothing" (found 2026-10-13 — the hint banner was just the first button noticed). Rule of thumb: when a page's buttons all die at once, extract the inline `<script>` and `node --check` it (or grep for `&quot;`/`&amp;` in it) before suspecting the handlers. Related same-day fix: never nest the AI feedback pane inside a UI container that is hidden by default — the story stream pane lived inside the (hidden-until-open) chapter pane, so a run triggered from the top-of-page hint banner streamed into an invisible element ("did nothing"); `#stream-pane` is page-level now.
